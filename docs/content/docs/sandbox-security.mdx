# 确定性沙箱与执行安全

> “大模型具备不确定性，智能体的行动力必须牢牢锁在受控的系统防线内。”

当 Agent 拥有了调用命令行、执行代码和检索网络的能力时，安全防线就是整个系统的生命线。TJUClaw 坚持**零信任防御（Zero-Trust Defense）**，构建了工业级执行沙箱。

---

## 基于 kubernetes-sigs/agent-sandbox 的标准沙箱

TJUClaw 的沙箱设计全面对齐 Kubernetes 官方社区 SIG 孵化的开源规范 [kubernetes-sigs/agent-sandbox](https://github.com/kubernetes-sigs/agent-sandbox)：

- **轻量容器级微隔离**：每个用户的独立任务分配隔离的临时容器环境，相互之间无文件与进程可见性；
- **资源使用硬限额**：对 CPU、内存、临时硬盘配额实施严格 cgroups 约束，防范恶意或死循环任务耗尽云端资源；
- **只读根文件系统与瞬态工作目录**：核心系统依赖目录以只读（`ro`）挂载，仅开放专门的 `/workspace` 作为产物输出地。

---

## 网络与系统调用限制

- **受控出站策略**：沙箱内部网络默认受限，仅放行天津大学校园公开服务与受信任的 API 域名，阻止内网刺探与非预期外联；
- **敏感指令拦截**：沙箱内核禁用危险系统调用（如未经许可的 raw socket 监听或内核模块加载操作）。

---

## 身份认证“永不碰模型”准则

在处理学生个人隐私与敏感凭据时，TJUClaw 确立了严格的铁律：

1. **Ory Kratos 企业级身份中枢**：用户登录、注册与会话验证完全由开源身份标杆 Ory Kratos 负责；
2. **同源 HttpOnly Cookie**：认证状态依托高安全级别的浏览器同源 Cookie，绝不在前端 JavaScript 中裸露明文 Token；
3. **模型不碰密码**：智能体只调度公开工具与被授权的受控 API，绝不在提示词或记忆中存储、传递学生的统一认证密码。
