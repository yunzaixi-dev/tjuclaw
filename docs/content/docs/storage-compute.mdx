# 极简架构与存算分离

> “有状态与无状态的混杂，是系统复杂性与运维灾难的根源。”

在传统全栈项目或重型微服务体系中，执行逻辑与持久化状态往往纠缠在一起。TJUClaw 汲取了维护大型 Kubernetes 集群的实战经验，全面贯彻**存算分离（Storage-Compute Separation）**的设计哲学。

---

## 核心设计思想

- **无状态计算沙箱**：所有的 Agent 思考、代码运行、工具调度（`tjucli`）均运行在瞬态的隔离沙箱中，即用即生、执行即销毁；
- **中心化持久存储**：任务状态、会话记录、用户记忆与产物文件由专属存储服务保障高可靠性；
- **接口极窄化**：各层之间仅通过确定性的 HTTP/JSON 契约进行数据流转，消除隐式依赖。

---

## 架构拓扑分层

```
+-------------------------------------------------------------+
|               计算层：无状态弹性执行沙箱 (Compute)             |
|   Agent Runtime (Pi)  │  tjucli 命令行管道  │  瞬态工作空间   |
+-------------------------------------------------------------+
                              │
               状态与产物同步 (HTTP / COS API)
                              ▼
+-------------------------------------------------------------+
|               存储层：中心化持久基础设施 (Storage)            |
|  PostgreSQL (元数据) │ 对象存储 COS (大文件) │ 独立长期记忆库   |
+-------------------------------------------------------------+
```

---

## 存算分离带来的工程收益

### 1. 真正的横向弹性伸缩
计算沙箱不需要维护任何本地硬盘状态，当高并发任务到来时，沙箱可以在云端集群中任意水平扩容，任务结束后立刻释放计算资源。

### 2. 免运维与故障自愈
即使某个 Agent 任务发生内存溢出、死循环或进程崩溃，崩溃的也仅仅是当前的无状态沙箱容器，核心数据库与对象存储分毫未损，系统具备天然的容灾边界。

### 3. 多端多设备即时恢复
由于所有状态都在权威存储中心，用户无论在电脑、网页还是手机端断开连接，重新上线后均可毫秒级恢复任务快照与执行上下文。
