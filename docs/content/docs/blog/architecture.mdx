# 系统总体架构

TJUClaw（面向天津大学校园场景优化的通用智能体平台）围绕真实学生场景，构建了一套连接前端客户端、云端服务、通用智能体与校园专有工具的系统体系。

---

## 整体架构视图

以下为目标架构与模块职责。各模块的独立验证不等于完整链路已上线；Pi 自动执行、沙箱交付与公网端到端流程仍需联合验收。

```text
Browser / Tauri WebView
  → same-origin /api/*  (Vite 开发代理或 EdgeOne/Nginx 剥离一层 /api)
    → Go net/http API   (后端路由无 /api 前缀，单 API 进程)
      → Kratos session + Cap 人机验证  (安全身份网关，无缝支持邮箱 OTP)
      → TASK_DATA_DIR 文件级草稿存储   (单 API 进程隔离，避免污染 Git)
      → PostgreSQL 权威任务/运行持久化存储

公开情报采集服务 (Bun + 独立专属 PostgreSQL) → RSS / Replay 事件重放流
  仅采集公开校园来源（微北洋、维基、课程等）；私有资料库权限完全由 Go API 保护，严禁跨库共享

WeKnora 知识引擎 (独立 Compose 隔离栈) → 文档接入 / 语义检索 / 租户 API Key
  环回 Loopback UI (:18180) 与应用 (:18181)；底层数据库物理隔离，非公开源，绝不与用户身份混淆

tjucli / tjucli-server → 权威公共课程与校园工具沙箱
  基于 TJUCLI_GRANTS_FILE 授权机制，智能体受控调用，无凭据泄露风险
```

## 核心模块与职责

### 1. 前端客户端（Frontend）
- **技术栈**：React 19、Vite、Tailwind CSS、Radix UI、Tauri（支持跨平台打包）。
- **职责**：提供学生交互界面，包括任务工作空间（Workspace）、目标输入、执行过程追溯（Trace）以及最终产物展示。
- **边界**：所有服务端通信严格基于同源 `/api/*`，不直接保存密码或敏感凭据，会话状态基于安全 HttpOnly Cookie。

### 2. 服务端与身份认证（Backend & Auth）
- **技术栈**：Go 标准库 `net/http` ServeMux、Ory Kratos（支持邮箱 OTP 验证码）、自托管 Cap（PoW 人机验证中枢）、PostgreSQL 与本地 `TASK_DATA_DIR` 文件存储。
- **职责**：负责用户同源鉴权、任务生命周期管理、工作空间元数据记录与草稿持久化。
- **设计原则**：
  - **身份网关严格守门**：`auth.Gateway.RequireSession` 是受保护 API 的绝对门禁，主体归属严格绑定自提供方 `Identity.ID`，严禁信任客户端请求体中的用户 ID；
  - **同源 Cookie 机制**：浏览器会话采用严格的 HttpOnly、Host-Only 安全 Cookie；Go API 绝不注册 `/api` 前缀路由；
  - **存储边界清晰**：开发环境草稿基于 `TASK_DATA_DIR` 单进程文件系统隔离，生产环境可平滑切换至 PostgreSQL。
### 3. 通用智能体运行时（Pi + Skill）
- **技术栈**：Pi 智能体运行时内核、领域专用 Skill 指引。
- **职责**：负责根据用户的自然语言需求分解目标、规划执行步骤、调用对应校园工具并归纳执行结果。
- **设计原则**：Skill 仅作为执行规范说明与参数指导，实际的权限控制与执行隔离由底层系统沙箱和网络策略强力保证。

### 4. 校园能力适配（tjucli）
- **技术栈**：Go 编写的高性能独立 CLI。
- **职责**：封装天津大学校园公开与私有资源访问（如课程分享平台、教学资料检索等），输出确定性的结构化 JSON，方便智能体消费。
- **设计原则**：明确区分“公开共享数据”与“学生个人隐私数据”，杜绝伪造成功状态与越权爬取。
### 5. 独立知识引擎与公开情报流（WeKnora & Crawler）
- **WeKnora 知识引擎**：基于独立 Compose 容器栈部署，仅绑定在环回地址（Loopback UI `:18180` / App `:18181`），为系统提供高效的文档切片、向量检索与知识库管理能力；与身份数据库严格物理隔离，绝不对公网直接开放。
- **公开情报采集服务 (Crawler)**：基于 Bun 运行时与独立专属 PostgreSQL 构建，负责定时抓取微北洋青年湖底、北洋维基、校园黄页、空闲教室等公开数据，生成标准单调递增的 RSS/Replay Feed，支撑校园知识动态沉淀。

## 基础设施与云端部署拓扑

在生产环境中，系统采用现代云边协同架构：
- **EdgeOne 边缘节点**：托管静态 Web 与 Docs 文档站，提供全站加速与 DDoS 防护，剥离 `/api` 前缀后向核心回源。
- **核心主机入口**：通过独立安全端口接入边缘回源请求，后端服务经 HAProxy / Nginx 调度至内部隔离容器。
- **服务隔离四象限**：认证中枢（Kratos + Cap）、产品 API（Go）、模型网关（NewAPI）、知识引擎（WeKnora）与情报采集（Crawler）运行在各自独立的隔离网络或专用存储中，数据库与管理端口绝不暴露于公网。
