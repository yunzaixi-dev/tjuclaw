# 一颗星值多少钱：把 660 条点星记录按毫秒排了一遍

> 数据：2026-09-30 从校内 GitLab 公开接口拉取的 49 个可见参赛项目、全部 660 条点星记录（每条含点星者账号与毫秒时间戳）。
> 本文**不点名、不列学号、不出现项目名**——项目以字母代称。要吐槽的是评分机制，不是同学。

## 先说结论

大赛的“星”本来应该回答一个问题：**这个作品有多少人觉得有用？**

把 660 条记录按毫秒时间戳和账号注册顺序重排之后，我们发现它回答的其实是另一个问题：**作者认识多少人，以及他们今晚有没有空。**

## 一、全景

| 指标 | 数值 |
|---|---|
| 点星记录 | 660 |
| 点过星的账号 | 498（平台共 974 个账号，一半点过星） |
| 有星的项目 | 37（12 个项目一颗星都没有） |
| 项目星数中位数 | **3** |
| 前三名合计 | 243 颗，占全场 37% |
| 只点过 1 个项目的账号 | **368（74%）** |
| 点过 3 个及以上项目的账号 | 21（4%） |
| 截止前 3 天（09-27 起）到达 | 314 颗，占 48% |
| 截止前一天单日 | **204 颗** |

一半的人点过星，但四分之三的人只点过一次；大多数作品几乎没星，少数作品吃掉了大头；一半的星挤在最后三天。

## 二、账号注册顺序：最诚实的时间戳

GitLab 的账号编号按注册顺序递增。编号相邻，意味着**前后脚注册**。

我们找了这样的形状：**两个编号相邻（相差不超过 2）的账号，在 10 分钟内给同一个项目点星。**

- 全场共 **297 对**，分布在 **14 个项目**里。
- 最长的一串：**37 个连续注册的账号**，给同一个项目点了星（该项目总共 54 颗）——这 37 个账号**此后再没给任何其他项目点过星**。
- 另一串：**32 个连续注册的账号**，在同一个晚上到第二天上午的 12 小时里给同一个项目点星，同样全部“只点这一个”。
- 还有一串 21 个连续账号，**3 个小时内**点完。
- 再看平台上最新注册的 200 个账号：**131 个点过星（65%）**；更早注册的账号，这个比例是 47%。

翻译一下：**有不少账号，是为了点这一颗星才注册的。**

> 公平起见：一个班一起注册、一起给同学点星，也会留下连续编号——这恰恰是我们想说的：星数量出来的是“能叫来多少人”，不是“多少人在用”。

## 三、名场面合集

**1. 买一送一套餐。**
星数第一、第二的两个作品（A 82 颗、B 81 颗），共享 **76 位**点星者。同一个人给两边点星的**间隔中位数 11 秒**，76 人里 72 人在两分钟内点完。其中还有一串 **15 个连续注册的账号**，在同一个小时里把两个作品都点了一遍。B 在截止前三天才创建，两天攒到 81 颗。

**2. 14 毫秒的友谊。**
A 的点星记录里，两个不同账号先后相差 **0.014 秒**。人眨一次眼要 100 毫秒。我们不下结论——可能是平台批量写入，也可能是手速惊人——但这个时间形状，在自然传播里基本不会出现。

**3. 新生开学礼包。**
入学才一个月的 2026 级新生贡献了 93 颗星（14%）。某作品 48 颗星里 25 位是新生，学号一段一段挨着，一分钟一个，像在排队领军训服。

**4. 深夜 23 点的集体觉醒。**
全天点星高峰不在“看展”的白天，而是 **22–23 点（140 颗）** 和 **14–16 点（200 颗）**。前者是宿舍群消息，后者……大概是某节课的课间。

**5. 自己给自己点星。**
28 次。这个我们理解，谁还没在深夜给自己的 README 点过赞。

## 四、点星的人长什么样

根据学号字段（首位学历、2–4 位入学年份、5–7 位学院）：

- **本科生 431 人**，硕士 61，博士 4；
- 2024 级最多（152），2023、2025 级各 111，**2026 级新生 76**；
- 两个学院合计贡献了近一半的点星者，与热门作品作者的学院高度重合。

**典型点星者：本科生，与作者同院，账号可能是这周才注册的，为一个项目来过一次，点完就走。**

## 五、为什么会这样

不怪同学。**只要把一个零成本、不看使用、截止前一晚也能冲的数字当成评分信号，它就一定会变成动员比赛。**古德哈特定律，百试不爽：

- **零成本**：点一下，不需要打开作品，更不需要用；
- **无法证伪**：点星的人有没有用过作品，排行榜不知道；
- **与时间无关**：两个月慢慢攒的 50 颗，和截止前一晚冲的 50 颗，排名上一模一样。

## 六、那该看什么

如果真想知道一个智能体好不好用，信号其实都在平台上：

- **真实使用**：有效会话、完成的任务数；
- **复访与留存**：第二天、第二周还有没有人回来；
- **广度加权**：只点一次就走的账号、刚注册就点星的账号，权重打折；
- **时间平滑**：截止前 72 小时的突增，打个折。

这些都不难算。难的是承认：**一颗星，更多时候衡量的是作者的社交半径，而不是作品的半径。**

## 写在最后

我们自己也是参赛者，也给朋友的作品点过星，这份账本里也有我们。所以这不是审判，是一面镜子。

希望明年的排行榜，能多一些“用过才点”的星，少一点凌晨 23 点的集体觉醒。
