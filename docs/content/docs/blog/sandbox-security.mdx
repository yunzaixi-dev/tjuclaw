# 确定性沙箱与执行安全

> “大模型具备不确定性，智能体的行动力必须牢牢锁在受控的系统防线内。”

当 Agent 拥有了调用命令行、执行代码和检索网络的能力时，安全防线就是整个系统的生命线。TJUClaw 坚持**零信任防御（Zero-Trust Defense）**，采用**腾讯云 Agent Sandbox（智能体安全沙箱）**构建工业级隔离环境。

---

## 腾讯云 Agent Sandbox 深度集成

TJUClaw 的代码执行与工具调度全面规划接入腾讯云专门面向 AI Agent 打造的 Agent Sandbox 托管能力：

- **秒级轻量微隔离容器**：每个用户的独立任务分配瞬态隔离的专属沙箱，相互之间完全不可见，杜绝跨租户文件泄露与进程串扰；
- **计算与存储严格解耦**：沙箱内部提供临时工作区 `/workspace`，任务执行过程中的临时文件在会话结束后即销毁，产物直接持久化至对象存储（COS）；
- **资源使用硬限额与配额管理**：对 CPU、内存、临时硬盘空间实施严格的资源配额与超时熔断控制，防范恶意脚本或死循环任务耗尽系统算力；
- **确定性工具注入**：将 `tjucli` 等校园能力工具与执行环境打包注入沙箱，保持宿主机与底层业务服务零风险。

---

## 网络与系统调用受控策略

- **受控出站策略**：沙箱内部网络默认受限，仅放行天津大学校园公开服务与受信任的 API 域名，阻止内网刺探与非预期外联；
- **敏感指令拦截**：沙箱内核禁用危险系统调用（如未经许可的 raw socket 监听或内核模块加载操作）。

---

## 身份认证“永不碰模型”准则

在处理学生个人隐私与敏感凭据时，TJUClaw 确立了严格的铁律：

1. **Ory Kratos 邮箱 OTP 身份中枢**：用户注册与登录均统一收口于邮箱动态验证码（OTP），由 Ory Kratos 进行安全会话派发与验证；
2. **自托管 Cap 人机防御**：所有验证码下发、账户操作均经由自托管 Cap 进行 PoW 挑战验证，防范恶意脚本自动化刷爆邮箱配额；
3. **同源 HttpOnly Cookie**：认证状态依托高安全级别的浏览器同源 Cookie，绝不在前端 JavaScript 存储明文 Token，防止 XSS 窃取；
4. **模型绝不接触密码与凭据**：智能体执行层只调度公开工具与被授权的受控 API，绝不在提示词、上下文或记忆中存储、传递学生的统一认证密码；
5. **服务数据边界物理隔离**：情报采集服务（Crawler）和知识引擎（WeKnora）各自拥有独立专用的数据库与网络边界，严禁与身份数据库混用，从根源杜绝数据越权穿透。
